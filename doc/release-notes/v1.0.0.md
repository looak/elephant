## v1.0.0 "Herd"
*Draft, results marked TBD are still being tested.*

The first complete, multi threaded Elephant. Elephants move as a herd, so do the search threads now: they share one
transposition table and spread out over different depths instead of all doing the same work. 1.0 also means every
advertised UCI option works and every valid UCI command gets an answer.

### Transposition table
- Buckets of 8 entries, one 64 byte cache line, a probe reads a single line. Each entry is one 64-bit word written and
  read atomically, threads sharing the table never see half an entry.
- Twice the entries per megabyte, and a new result always finds a slot, the least valuable entry in the bucket makes
  room. The old table dropped shallower results, exact scores too, once a slot held a deeper entry from the same search.
- A fail-low no longer wipes the stored move.
- Every megabyte of `Hash` is used, `Hash 100` was 64 MB before. The maximum goes from 1 GB to 32 GB, and the table is
  cleared with all threads.

### Lazy SMP
- Thread 0 is the main thread, it reports, manages time and its move is played. It stops the helpers when it's done.
- Helpers skip iterations in staggered blocks, they search ahead of the main thread and fill the table with deeper
  results.
- `info nodes` and `go nodes` count every thread.
- `debug on` prints what the helper threads search as info strings.

### UCI
- `ucinewgame` clears the transposition table, games no longer influence each other.
- `go nodes`, `go mate` and `go searchmoves` work, they used to stop the engine without a bestmove.
- A malformed command reports an `info string error` and the engine keeps running.
- `info hashfull`.
- `Threads` 1–64, `Hash` 1–32768.

### Fixes
- Threefold repetitions after a double pawn push were missed: the en passant square was set and hashed even when no
  pawn could capture, fastchess reported "PV continues after threefold repetition".
- TBD: side to move missing from the hash of black-to-move FENs (#13), a non-pawn move onto the en passant square
  flagged as a capture (#14), the fifty move counter after a pawn push (#15).
- Bench measured mostly the OS mapping in a new 64 MB table per position, it now measures the search: about 3.2M nps
  instead of 1.0M on a Ryzen 9 9900X, the same node count.
